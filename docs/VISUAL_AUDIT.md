# 《星潮守望者》视觉审计与整改复验

> 视觉方向：D「日光远征动画」
> 初审日期：2026-08-09
> 整改复验：2026-08-10
> 验收画布：540×960、540×1170、540×1200、720×960

## 1. 审计范围与方法

本轮以实际运行画面为准，覆盖远征地图、角色、装备、技能培养、图鉴、三生态战斗、HUD、六项技能、敌我受击、拾取、三选一、胜利结算以及大厅和三生态音频。

复验包含：

- 四档画布与 Safe Area 截图。
- 三生态、升级入场、结算首拍和最终态截图。
- 玩家、敌人、危险、拾取物、摇杆和 3 个自动技能槽的读战检查。
- 43 个 WAV 的格式、时长、唯一性、响度分层和 Godot 运行时 Cue 契约检查。
- 全量自动化、架构行数门禁和运行时 smoke。

专用星潮技能截图入口仍因既有夹具只生成 3 个初始敌人、低于夹具要求的 5 个而中止；失败发生在技能展示准备前，不属于产品视觉回归。技能判断来自实际战斗、运行时轨迹和其他演示截图。

## 2. 总体判断

方向 D 已从“骨架成立”推进到“核心战斗与主流程可形成统一成片感”。本轮没有发现新的 P0 读战阻断，10 个原问题均已落地处理；其中 8 项完成自动与视觉复验，音频仍需真人用耳机和手机外放做最终听感确认，局外等宽页签仍可作为后续 P2 抛光项。

本轮没有改变玩法、数值、内容 ID、存档 Schema、掉落规则、按钮行为或音频 Cue ID。

## 3. 最影响美感的 10 个问题与整改结果

### 1. 彩晶火山背景破坏读战和危险色语义

- 优先级：P0
- 类型：美术素材、动画反馈
- 状态：已完成
- 原问题：大面积珊瑚红裂隙和重复晶体持续占用 Danger 色，角色、怪物和警告线对比不足。
- 修改建议：以冷灰岩板为主体，降低纹理频率与裂隙亮度，只在真实危险附近使用珊瑚红。
- 本轮实施：重制 1024×1024 无缝冷灰岩板，保留稀疏青色晶簇与低亮裂隙；同步降低火山装饰密度、饱和度和程序裂隙亮度。
- 复验：运行时火山地面由高频红纹改为中低频冷灰，角色、敌人、拾取和警告重新成为一级焦点。

### 2. 六项技能的战场轮廓没有全部落实

- 优先级：P0
- 类型：美术素材、动画反馈
- 状态：已完成
- 原问题：范围技能大量复用圆环、放射线和亮色闪帧，缩小或叠加后容易混淆。
- 修改建议：为每项技能固定蓄势剪影、运动轨迹、命中峰值和收尾残留，圆环只作辅助。
- 本轮实施：日轮改为离散轨道节点；霜潮改为定向冰晶齿波；陨星加入纵向坠落线和缺口落点；凤凰保留双翼围合的心形负空间。
- 复验：星芒枪、日轮、霜潮、烬羽、陨星和凤凰可依靠形状与运动方向区分。

### 3. 敌人受击与玩家受伤缺少方向性冲击

- 优先级：P0
- 类型：UI、动画反馈
- 状态：已完成
- 原问题：敌人仅短暂染色，玩家使用均匀全屏红闪，混战中难判断伤害来源。
- 修改建议：敌人加入来源方向位移、粗轮廓和材质碎片；玩家改为中心透明的方向性边缘受创。
- 本轮实施：敌人加入 65 ms 内闪、1.4 px 粗轮廓、4 px 来源反向位移和分类碎片；玩家加入 160 ms 方向性珊瑚红边缘 Shader、镜头震动和 220 ms 生命条缺口。
- 复验：高速敌弹使用扫掠前一位置作为来源，方向链路有专门回归断言；局部/全局坐标混用也由测试拦截。

### 4. 胜利结算先出现空白大卡，最终像移动端报表

- 优先级：P0
- 类型：UI、动画反馈
- 状态：已完成
- 原问题：首拍约 133 ms 只有空白大卡，最终英雄、奖励、统计、构筑和按钮等权排列。
- 修改建议：首拍先承接胜利、英雄和主奖励，再依价值顺序展开完整信息。
- 本轮实施：100 ms 首拍同步显示结果标题、英雄/徽章和主奖励短卡；随后展开来源、次级奖励、统计和构筑；仅保留一个日照金主操作。
- 复验：首拍无空白总卡，英雄经验为唯一一级奖励焦点，完整结算信息不丢失。

### 5. 三选一仍是三张同构白卡

- 优先级：P0
- 类型：UI、美术素材、动画反馈
- 状态：已完成
- 原问题：技能、遗物和补给使用近似结构，品质主要依赖颜色，错峰入场不可感知。
- 修改建议：按内容类型改变标题签和面板轮廓，品质用压线、扣件和徽章结构表达。
- 本轮实施：三类卡使用不同分形轮廓与语义色；品质采用 1/2/3 层结构与扣件；卡片上移 16 px、错峰 45 ms，结束时间为 230/275/320 ms。
- 复验：200 ms 仍可观察第三张卡入场，完整揭示不超过 320 ms，选择逻辑保持不变。

### 6. 音频覆盖完整，但声音本体有合成占位感

- 优先级：P1
- 类型：音频
- 状态：已实现，待真人听感复验
- 原问题：4 首 BGM 与 39 个 Cue 依赖同一波形模板和近似峰值，材质与生态身份不足。
- 修改建议：保留 Cue、总线和存档契约，建立帆布、轻木、搪瓷、短弦和自然风五个音色家族，并按信息优先级分层。
- 本轮实施：重制全部 43 个 WAV；四首 BGM 使用不同调式、节奏和乐器组合但共享短动机；技能、拾取、受伤和 UI 使用不同材质组合。
- 复验：43/43 文件哈希唯一，44.1 kHz、16-bit PCM；Cue 为单声道 0.11～0.92 秒，BGM 为 32 秒双声道；Godot Cue、并发和 Ducking 契约通过。
- 后续建议：用耳机与手机外放各试听一次，重点确认搪瓷高频尾音和连续混战的命中/受伤密度。

### 7. 角色、装备、训练和图鉴呈现网页卡片后台

- 优先级：P1
- 类型：UI、美术素材
- 状态：已完成结构整改，保留 P2 抛光空间
- 原问题：统一白卡、等宽页签、规则网格、圆形加号空槽和仅靠颜色的品质表达形成后台模板感。
- 修改建议：以英雄舞台、连续属性、装备结构和图鉴连续底板替代卡片海；品质增加结构编码。
- 本轮实施：角色页改为连续英雄舞台；装备槽并入舞台，背包为四列紧凑陈列；图鉴改为连续纸页和三列网格；空槽使用部位剪影；训练锁定行加入锁徽章、状态名和解锁说明。
- 复验：品质的 1/2/3 层压线、扣件和边框均可独立辨识；局外白卡海明显减少。两排等宽主导航仍可在后续改为更自由的织带索引。

### 8. 战斗 HUD 过重，字体、数字和颜色语义不统一

- 优先级：P1
- 类型：UI
- 状态：已完成
- 原问题：顶部两层结构占用约 150 px，满血持续为红色，教学条过宽，`Lv.`、`LV.` 和罗马等级混用。
- 修改建议：压缩为连续信息条，满血使用非危险色，所有功能文字不低于 14 px，并统一数字规则。
- 本轮实施：主 HUD 为 504×72，路线状态条为 504×48；满血使用支持绿，30% 以下切 Danger；教学与暂停控件减重；统一 `LV.N` 和 `I/II/MAX`。
- 复验：720×960 主 HUD 与 StageHud 均位于 x=108，横向偏差 0 px；四档无裁切。

### 9. 非 9:16 画布存在拼接缝和手机画框感

- 优先级：P1
- 类型：UI、美术素材
- 状态：已完成
- 原问题：高屏出现黑横缝，3:4 使用不同裁切的三张背景，中央像嵌入的手机壁纸。
- 修改建议：只渲染一个环境背景，中央设计区保持稳定映射，额外区域只延伸低频环境。
- 本轮实施：路线图内部背景节点保留为兼容占位但不再渲染；全屏只使用一个背景实例。高屏连续延伸；宽屏侧区由去细节边缘采样和雾化生成，并在中央内侧 28 px 渐变，避免复制木框、藤蔓和风车。
- 复验：四档无黑缝、硬接缝和镜像物件；540 逻辑内容、HUD、图鉴和底部导航保持对齐。

### 10. 拾取物移动与落点没有完成信息闭环

- 优先级：P2
- 类型：UI、美术素材、动画反馈
- 状态：已完成
- 原问题：拾取物线性移向玩家，收集后的反馈都停在角色位置，经验、治疗和状态效果缺少明确去向。
- 修改建议：统一 180～220 ms 短弧牵引，并把不同拾取物反馈送向对应 HUD 目标。
- 本轮实施：拾取物使用二次贝塞尔短弧；经验飞向经验条，治疗飞向生命条，磁吸与加速飞向状态条并触发目标闪光，爆破保持战场峰值。
- 复验：拾取、数值和 Cue ID 不变；运行时吸附、收集、HUD 目标闪光和内容发现链路通过。

## 5. 当前值得保留的部分

- 两名英雄的头身比、五官、服装、武器轴和标志性色块。
- 四类怪物的主体设计、厚薄差异和体量层级。
