# 《星潮守望者》战力、装备与角色中心实现说明

> 适用版本：Godot 4.7 / 本地存档 schema 6
> 更新日期：2026-08-03

## 1. 玩家闭环

局外流程统一为：

```text
开始页选择关卡
  ↕ BottomBar
角色页选择出战英雄
  → 查看等级与战力
  → 穿戴武器 / 护甲 / 饰品
  → 分配专属技能点
返回开始页
  → 对比当前战力与关卡推荐战力
  → 踏入星门
```

开始页不再重复弹出第二套英雄选择页。“踏入星门”直接使用角色页中已经持久化的当前英雄。

## 2. 永久属性快照

`HeroStatResolver` 是角色页与战斗共同使用的唯一永久属性解析入口。输入为：

- 英雄目录基础属性。
- 英雄经验与等级成长。
- 三项专属技能的永久训练。
- 当前武器、护甲和饰品。

输出包含：

```text
hero_xp / level / skill points
resolved_stats
skill_modifiers
equipment
power
```

战斗开始时只读取一次该快照，再注入 `Player`、`SkillController` 与 `PickupSystem`。进行中的战斗不会被局外换装或加点修改。

## 3. 战力公式 v1

```text
总战力 = 1000 基础战力 + 等级战力 + 技能训练战力 + 装备战力
```

战力只描述局外永久成长，不包含本局技能等级、分支和遗物，也不会再次作为伤害倍率参与战斗。

等级战力：

```text
20 × 全局伤害加成百分比
+ 10 × 最大生命加成百分比
```

当前每级提供伤害 `+1.5%`、最大生命 `+1%`，因此 Lv.1 为 1000，Lv.10 无训练时为 1360。

技能训练战力按真正生效的伤害、治疗、范围、弹速和攻击频率计算。装备战力按伤害、有效生命、攻击频率、移速、范围、弹速和拾取范围计算。全部权重集中在 `PowerRatingConfig`，角色界面不自行计算战力。

三关推荐战力为：

| 关卡 | 推荐战力 |
| --- | ---: |
| 风铃草原 | 1000 |
| 金砂绿洲 | 1100 |
| 彩晶火山 | 1250 |

推荐战力只作提示，不是硬门槛；怪物也不会根据英雄战力动态增强。

## 4. 装备

永久装备与单局遗物是两个独立系统。装备包含三个固定槽位：

| 槽位 | 普通装备 | 首通装备 |
| --- | --- | --- |
| 武器 | 启程星杖 | 第一关：风弦短弓 |
| 护甲 | 风铃护衣 | 第二关：彩晶背心 |
| 饰品 | 风铃叶坠 | 第三关：时砂棱镜 |

新档和旧档都会通过稳定奖励收据 `starter_equipment_v1` 幂等获得三件普通装备。三关首通固定装备均为稀有品质，并使用稳定奖励 ID 与实例 ID；异常冲突解除后，后续通关会自动补发。

每次胜利（包含首次通关）额外保证掉落 `1–4` 件随机装备。装备定义具有独立 `content_tier`，每关的 `EquipmentDropTableConfig` 决定允许出现的装备、条目权重、品质权重和初始等级区间：

| 关卡 | 装备内容阶级 | 普通/稀有/顶级 | 初始等级 |
| --- | ---: | --- | --- |
| 风铃草原 | 1 | 82% / 16% / 2% | Lv.1 |
| 金砂绿洲 | 1～2 | 72% / 23% / 5% | Lv.1～2 |
| 彩晶火山 | 1～3 | 62% / 28% / 10% | Lv.1～3 |

品质本身的属性和升级上限保持统一：

| 品质 | 属性倍率 | 等级上限 | 卡片背景 |
| --- | ---: | ---: | --- |
| 普通 | 1.00 | Lv.5 | 灰色 |
| 稀有 | 1.35 | Lv.10 | 绿色 |
| 顶级 | 1.75 | Lv.15 | 紫色 |

最终属性为 `品质倍率 ×（基础属性 + 每级成长 ×（等级 - 1））`。背包卡、已装备槽位和详情面板统一使用品质对应的背景色、同色边框与文字色，选中态只叠加金色光晕。同名装备可以跨品质作为升级材料；每次升级消耗一件同名装备并使目标 `+1` 级。已锁定或已穿戴的装备不能作为材料，目标装备的品质不会因升级改变。

同一装备实例不能同时被两名英雄使用。加载存档时会修复：

- 未知装备目录 ID。
- 非法品质或装备等级。
- 装备槽位不匹配。
- 同一实例被多个英雄引用。
- 不存在的装备实例。

当前版本不包含品质晋升、随机词条和套装。升级只消耗同名装备，不引入第二种材料或货币。

## 5. 存档 schema 6

schema 6 在 schema 5 英雄经验模型之上，将品质和等级收敛为装备实例字段：

- schema 4 的 `mastery_xp` 迁移为 `hero_xp`。
- 等级仍由经验推导，不重复保存。
- 原技能训练完整保留。
- 新增当前出战英雄、装备背包、各英雄装配和已领取奖励 ID。
- 旧装备的 `enhance_level` 自动迁移为从 Lv.1 开始的 `level`，品质按原装备默认品质补齐。
- 战力与最终属性不写入存档，始终由静态目录和实际成长数据重新计算。

旧字段只在加载兼容与回归测试中保留；新存档不再写入 `mastery_xp`。

## 6. 前台界面

`FrontendShell` 统一维护两个页面：

- 开始：关卡轮播、动态关卡预览、当前/推荐战力和进入按钮。
- 角色：英雄切换、动态角色、状态、装备和技能三个栏目。

`BottomBar` 锚定真实安全区底部，不放入固定 `540 × 960` 设计框。页面内容为底栏预留空间；9:16、19.5:9、20:9 和 3:4 均有自动化布局与截图回归。

角色页只运行一个当前英雄的完整帧预览；其他英雄使用按钮切换。隐藏页面会停止角色与关卡预览动画，避免后台持续处理。

## 7. 角色完整帧动画

两名英雄共用 `HeroRig2D`：

- 1 个 `AnimatedSprite2D` 完整角色绘制组件，不再拆分头、手臂、腿或武器。
- 每名英雄 6 张 512×512 透明姿势帧，脚底统一位于 y=488。
- `HeroSpriteCatalog` 将姿势组合为运行时动作。
- `menu_idle`、`menu_react`、`idle`、`run`、`cast`、`hit`、`victory` 七个状态。
- 左右朝向使用完整角色水平镜像，不再通过负缩放穿过零宽。
- `idle` 使用整体呼吸，`run` 在接触帧与腾空帧之间循环；施法、受击、胜利使用完整关键姿势，肩、髋、衣服和武器不会在运行时重新拼接。

同一角色场景用于开始页、角色页、战斗和结算。生成姿势缺失时回退角色原始完整立绘，避免新增英雄因素材未齐而无法运行。

桌面开发场景 `hero_rig_tuner.tscn` 提供 7 个动作和 96、188、360 像素三档预览，可暂停或从首帧重播。它只调用 `HeroRig2D` 稳定接口，不依赖内部帧播放器。

原创完整帧素材与生成说明位于：

- `assets/generated/hero_chibi/`
- `assets/generated/equipment/`

## 8. 扩展入口

- 新装备：向 `content/equipment.tres` 增加稳定 ID、内容阶级、基础属性和每级成长。
- 新装备掉落：把装备加入目标关卡的 `EquipmentDropTableConfig`，配置条目权重、品质曲线和初始等级区间。
- 新装备奖励：在目标关卡 `RewardConfig.first_clear_equipment_reward` 中增加稳定奖励 ID 与实例 ID。
- 新战力权重：修改 `PowerRatingConfig` 并提升公式版本。
- 新英雄：提供 `HeroCatalog` 数据、三项技能和同名的 6 张完整姿势帧。
- 新存储后端：实现 `ProfileRepository`，不修改战斗系统。

## 9. 自动化覆盖

当前 26 套统一测试额外覆盖：

- Lv.1、Lv.10、训练和装备的战力黄金值。
- 穿戴、卸下、跨英雄互斥和属性恢复。
- 新手装备与首通装备奖励幂等。
- schema 4 → 5 迁移与重载。
- 角色页三栏目、BottomBar、当前英雄持久化。
- 角色选择或换装后开始页战力同步。
- 两名英雄、单一完整角色组件、7 个状态、统一脚底基线、左右镜像与完整立绘回退。
- 帧预览器的 7 个动作、三档尺寸、暂停/继续、从首帧重播和稳定接口边界。
- 永久移速和拾取范围进入真实战斗。
- 两名英雄的伤害、冷却、范围和投射物速度装备属性进入真实技能运行时。
- 首通装备在异常冲突解除后可以自动补发，且结算显示实际装备名称。
- 每次胜利掉落 1–4 件装备、逐关内容/品质/等级曲线、三档品质等级上限与同名消耗升级。
- 四种屏幕比例的安全区与截图回归。
